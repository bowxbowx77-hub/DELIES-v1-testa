# DEVVAULT

Самостійна платформа для зберігання, версіонування та публікації проєктів. React + TypeScript працюють з HTTP API на Flask; метадані зберігаються в SQLite, вміст файлів — у файловому сховищі за SHA-256. Для роботи не потрібні зовнішні сервіси, токени або LocalStorage.

**Це сховище з файловими знімками, а не Git-сервер:** є історія, відновлення, імпорт і ZIP-експорт, але немає `git push`, гілок чи виконання збірок користувача.

## Швидкий запуск

Потрібні Linux або macOS, Node.js 22+, npm, Python 3.11+ із `venv`. На Debian/Ubuntu для створення середовища потрібен пакет `python3-venv`.

```sh
npm ci
npm run build
npm start
```

Відкрийте **http://localhost:3000**. `npm start` створить `.venv` та встановить зафіксовані в `requirements.lock` Python-залежності. Gunicorn обслуговує і застосунок, і `/api` на одному порту. `PORT=4000 npm start` змінює порт.

Для розробки:

```sh
npm ci
npm run dev
```

Vite з HMR: **http://localhost:5173**; внутрішній API: `127.0.0.1:8000`. Браузер завжди звертається за відносними URL, а Vite проксіює `/api`. Попередній перегляд підтримує хости `*.e2b.app`. Зовнішні шрифти чи CDN під час роботи не використовуються.

## Перший проєкт

1. При першому відкритті панелі ви отримуєте **власний ізольований гостьовий простір**. П’ять стартових проєктів містять справжні файли, ліцензії та знімки. Це не спільний тестовий обліковий запис. Метрики та журнал обчислюються зі збережених даних; лічильник скачувань починається з нуля.
2. **Create account** у бічній панелі або меню аватара закріплює цей простір за email і паролем. Реєстрація не замінює файли. **Sign in** перемикає на вже створений акаунт. Гостьовий доступ прив’язаний до cookie на 30 днів: для тривалого зберігання доступу зареєструйтеся до очищення cookie чи зміни пристрою.
3. **New repository** → назва, опис, іконка, ліцензія, видимість. Нові репозиторії приватні за замовчуванням. README можна створити одразу.
4. **Upload files** → виберіть репозиторій. Додайте окремі файли, ZIP або каталог через **Select folder**. Можна вказати опис змін. Одна успішна операція — один новий знімок. Існуючі шляхи оновлюються, решта файлів залишаються. Структура каталогів відтворюється зі шляхів файлів; порожні каталоги не версіонуються.
5. На сторінці проєкту відкривайте папки, переглядайте текст, перейменовуйте чи видаляйте файли, завантажуйте ZIP поточної або давнішої версії. **Version history → Restore** створює нову версію, не перезаписуючи історію.
6. **Repository settings → Public → Save changes** публікує репозиторій. **Copy public link** дає сталу адресу `/r/<id>`: перейменування її не змінює. Анонімному читачеві не потрібні реєстрація, cookie або гостьовий простір. Публікується **вся історія файлів**, не лише остання версія. Повернення в Private закриває доступ для інших.
7. **Move to Trash** негайно вимикає публічний доступ. **Restore** повертає репозиторій разом з історією. Остаточне видалення потребує точного введення назви і не знищує вміст, на який посилаються інші проєкти.

Інші розділи: особисті репозиторії, публічний каталог, пошук `Ctrl/Cmd + K`, профіль, налаштування, зміна пароля, журнал та сповіщення з позначенням прочитаного. Інтерфейс адаптується до телефону й клавіатури; анімації враховують `prefers-reduced-motion`.

## Структура репозиторію

```text
web/
  main.tsx, store.tsx       оболонка, маршрути, сесія, навігація
  lib.ts, style.css         клієнт API, типи, дизайн-система
  components/              діалоги, форми, компоненти та SVG-ілюстрація
  pages/                   overview, проєкти, файли, версії, акаунт, журнал
server/
  app.py                   HTTP API, контроль доступу, статика SPA
  core.py                  схема SQLite, транзакції, сесії, запити
  storage.py               безпечний імпорт, блоби, маніфести знімків
  starters.py              вихідні файли п’яти стартових проєктів
scripts/
  setup_backend.py         ізольоване Python-середовище
  dev.py, serve.py         запуск розробки / Gunicorn
  maintenance.py           резервні копії, перевірене відновлення, GC
  test.py, browser_server.py  запуск ізольованих тестів
public/                    favicon
Dockerfile, compose.yaml   контейнер і постійні томи
deploy/                    конфігурація HTTPS через Caddy
tests/                     інтеграційні та браузерні тести
docs/                      API, безпека, експлуатація та розгортання
.github/workflows/         автоматична перевірка збірки та тестів
```

Робочі каталоги **не додаються в Git**:

```text
vault-data/
  vault.sqlite3            користувачі, сесії, проєкти, події, версії, шляхи
  blobs/<prefix>/<sha256>  незмінний вміст файлів
  stage/                   тимчасові файли імпорту й експорту
dist/                      результат npm run build
```

## Перевірки

```sh
npm test                          # API + БД + реальні файли + backup/restore
npm run build                     # строгий TypeScript + production bundle
npx playwright install chromium   # один раз для браузерних тестів
npm run test:e2e                   # окремий тестовий сервер і тимчасова БД
```

Для системного Chromium використовуйте `CHROMIUM_EXECUTABLE=/path/to/chromium`. На чистому Linux у Chromium можуть знадобитися системні бібліотеки (`npx playwright install --with-deps chromium`). Тести не змінюють робочий `vault-data`.
