# DEVVAULT Pocket для Android

**Інсталяційні пакети:** [GitHub Releases](https://github.com/bowxbowx77-hub/DELIES-v1-testa/releases). Оберіть підписаний `.apk`, а не CI-артефакт `unsigned`. Android 8.0 / API 26 і новіший, сучасний Android System WebView (Chrome 110+). Потрібне вільне місце для знімка й тимчасового експорту. Google Play, Google-акаунт та сторонній API-ключ не потрібні.

## Перші кроки

1. Відкрийте **Сховище → Новий проєкт**. У **Додати файли** виберіть документи або ZIP. Для надійного перенесення цілої папки через системний файловий менеджер використовуйте ZIP. Зберігаються відносні шляхи. Вибрані документи копіюються, оригінали не змінюються. Малий текстовий файл можна також створити чи відредагувати вручну.
2. **Версії** відкривають попередній вміст; «Відновити» додає новий знімок. **ZIP** передає один знімок через системне меню Android. **Резервна копія** передає `.dvault` з усією історією й дедуплікованими байтами. Виберіть одержувача, який зберігає файл **поза застосунком**. Копія не зашифрована — зберігайте її у захищеному місці. З головної сторінки «Відновити копію» перевіряє хеші й створює окремий приватний проєкт.
3. Видалений проєкт спершу йде до кошика. Для остаточного видалення потрібно ввести його назву. Втрачаються лише локальні знімки та їхні непотрібні об’єкти; дублікати, потрібні іншим проєктам, залишаються. Локальне видалення не видаляє серверну публікацію. **Деінсталяція або очищення даних Android стирає всі локальні проєкти.**
4. Необов’язково: розгорніть бекенд **цієї версії** за [інструкцією HTTPS](OPERATIONS.md), відкрийте **Сервер**, введіть його базову адресу `https://ваш-домен` без `/api`. Зареєструйтесь або увійдіть. «На сервер» показує призначення та видимість до передавання. Нова копія починається з приватної чернетки; цілісний знімок і вибрана видимість записуються разом. У разі помилки першого імпорту на сервері може залишитися порожня приватна чернетка. Наступне передавання в той самий акаунт оновлює ту саму адресу; конфлікт версій не перезаписує чужі зміни. Публічний режим відкриває усі версії **серверного** проєкту, а не локальну історію. Копіювання з сервера на пристрій — окрема дія. Автоматичного фонового двобічного sync немає.

## Вміст і обмеження

- `mobile/src/*.rb`: Ruby-клієнт (інтерфейс українською, сховище, HTTPS, резервування). Під час збірки Ruby2JS компілює **тільки довірений код застосунку** в JS для Android WebView. Це не інтерпретатор Ruby для користувацьких проєктів.
- `mobile/core/vault.cpp`: C++17 → WebAssembly у тому самому APK, незалежно від ABI процесора. Перевірка шляху, метаданих ZIP, типів, певних сигнатур і секретів. Розпакування — zip.js (stored/deflate), CRC, обмеження оголошених і фактично розпакованих байтів. Не антивірусна гарантія.
- `mobile/scripts/*.sh`, `*.rb`: компіляція, штатна оболонка Capacitor/Gradle, оформлення, перевірка та підпис. HTML/CSS для розмітки; Android, WebView та бібліотеки містять власний платформний код. Існуючий сервер Flask/SQLite та вебклієнт не переписані мобільними мовами.
- Файлові об’єкти за SHA-256: приватний Android `files/objects/`, проміжні файли `files/stage/`; індекси та маніфести — IndexedDB приватного WebView. Сервер, Git і зовнішні CDN не беруть участі в локальному імпорті. Під час збою маніфест не показує частково записану версію. Недосяжні об’єкти прибираються при відкритті або очищенні кошика. Експорти, які віддаються через Android Share, тимчасово лежать у `cache/exports/` до наступного запуску. Вбудоване резервування Android вимкнено.
- На пристрої: 100 проєктів включно з кошиком, 100 версій на проєкт, 2 000 файлів / 128 МіБ на знімок, 32 МіБ на файл, 1 ГіБ унікальних даних; текстовий перегляд і редактор до 96 КіБ. `.dvault`: до 120 МіБ унікальних даних, 1 999 об’єктів і 4 МіБ маніфесту; більші історії експортуйте потрібними знімками. Серверні ліміти: [SECURITY.md](SECURITY.md).
- Лише HTTPS. Пароль і bearer не пишуться на диск. Токен першої сторони живе в RAM, на сервері зберігається тільки його хеш з окремим префіксом і терміном до 12 годин. Веб-cookie не використовується для мобільного origin. Жодної телеметрії чи вбудованого загальнодоступного бекенда. Не вводьте облікові дані на неперевірений сервер.

## Відтворити збірку та перевірки

Linux/macOS shell, Node 22/npm, Ruby 3.2+ з OpenSSL, JDK 21, Android SDK Platform 35 та Build Tools 35.0.0 (`ANDROID_HOME`); `clang++` із wasm-ld або Zig 0.13.0. Залежності Gradle потрібно завантажити під час першої збірки; Gradle wrapper входить у шаблон хоста. Android SDK-пакети та ліцензії заздалегідь встановлює оператор.

```bash
cd mobile
npm ci
# export ZIG=/абсолютний/шлях/до/zig   # або CLANGXX=clang++ з wasm-ld
./scripts/package.sh                  # out/devvault-1.1.0-unsigned.apk
# Тільки тест локальних assets, без Android SDK: ./scripts/build-web.sh
cd ..
npm ci && npm test                    # включає ізольовані тести мобільної API
npx playwright install chromium
npx playwright test -c mobile/tests/playwright.config.cjs
```

Тести Pocket працюють із зібраними assets, тимчасовим HTTPS та SQLite, а не з production. У браузері байти зберігаються в полі `Blob` IndexedDB; Android використовує приватний Filesystem. `mobile/tests/device.rb APK` додатково перевіряє встановлення, офлайн-редагування та читання після force-stop **на одноразовому емуляторі**, очищаючи там дані тестового пакета. Не запускайте на телефоні з власними проєктами.

## Підпис і патчі

Публічний сертифікат: `mobile/signing/release.pem`. Для офіційного оновлення потрібні той самий приватний ключ, `appId` і більший `VERSION_CODE`. Захищено скопіюйте каталог видавця з `release.key` і `key.pass` у власне офлайн-сховище; **не публікуйте жоден із цих файлів**. Приватний матеріал не міститься в Git, Docker, `.dvault`, CI, APK чи релізі. Без ключа можна підписати лише власну окрему інсталяцію, а не оновити офіційну поверх даних користувача.

1. Оновити `VERSION`, `VERSION_CODE`, release notes, перевірити lock-файли і відправити чинну гілку. Workflow **Android APK** компілює, збирає і тестує. Запит на підпис містить SHA-256 всього unsigned APK і Android v2 content digest.
2. На довіреному комп’ютері перевірити джерело, гілку й успішний CI. `ruby mobile/scripts/approve-release.rb RUN_ID` підписує лише digest цієї збірки. Якщо попередній кандидат не пройшов тест пристрою й тег ніколи не публікувався, виправте код, дочекайтеся нової збірки й додайте `--replace-unpublished`. `DEVVAULT_SIGN_DIR` може вказувати за межі репозиторію, інакше читається локальний ігнорований `.devvault-signing/`. `init-signing.sh` **тільки** для нового незалежного видавця; скрипт не замінює наявну ідентичність.
3. Комітити лише публічний `mobile/releases/VERSION.json`. **Publish signed Android release** завантажує конкретний артефакт, звіряє обидва digest-и та сертифікат, додає v2-підпис, запускає офіційні `apksigner verify`, `zipalign`, `aapt` і smoke-тест Android. Лише після успіху створює GitHub Release з тегом на коміті видачі; його код застосунку й бекенда має точно збігатися із комітом збірки в `signing-record.json`. Можуть відрізнятися лише публічне схвалення, нотатки та перевірка видачі. Не перезаписує існуючий реліз.
4. Користувачі можуть перевірити `sha256sum -c SHA256SUMS.txt` у каталозі всіх assets або `apksigner verify --verbose --print-certs DEVVAULT-Pocket-1.1.0.apk`. Для окремої тестової інсталяції можна підписати unsigned APK звичайним SDK `apksigner sign --ks ВАШ_ТЕСТОВИЙ_КЛЮЧ --out test.apk …`.
5. Вихідний `.patch` застосовується до чистого дерева вебверсії `547b973` через `git apply --check patchfile && git apply patchfile`. Patch **не** встановлюється на Android замість APK.
